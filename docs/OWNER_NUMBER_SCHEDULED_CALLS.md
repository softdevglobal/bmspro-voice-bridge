# Owner scheduling by phone number

Talk to Sophie supports an explicit destination number even when no customer account or call history exists. `prepare_customer_scheduled_call` accepts `number` with optional `customerName`, date, time, category, instructions and optional business DID. A name is no longer required when a number is provided; the model must not force a lookup, registration or history match. A numeric `find_call_customers` search also redirects the model to direct number preparation.

For number-only calls, the backend normalizes the owner's supplied Australian or international Sri Lankan number, reads the full normalized number and call details back, and retains the existing explicit owner confirmation gate. National numbers use the existing Australian normalization; include +94 for Sri Lankan destinations. No customer profile is created or updated, and an explicitly supplied number is never silently replaced with a saved customer's number. Saved-customer scheduling without a supplied number retains exact name/email disambiguation and contact revision checks.

Prepare, confirm and dial recheck the current owner, business route, enabled flags, call logs, business timezone/hours, supported number and customer opt-out. All mapped reception DIDs are refused as direct destinations to prevent loops. Scheduling remains within 30 days, with the existing two-hour execution window and duplicate protections. A recipient-requested later callback retains direct-number metadata and does not require a customer record.

Direct-number calls use `recipientSource: owner_number`, null customer ID and `OWNER_NUMBER_SCHEDULED` as the pending state. This isolates them from older workers that require a customer document. The updated due reader shares the existing six-call batch and status/scheduledAt index; the UI maps the state to Scheduled and permits cancellation before claiming. Saved-customer calls retain SCHEDULED.

When a recipient name is unknown, the bridge introduces Sophie and the business, says the owner asked her to contact this number, and asks whether now is a good time. It does not ask to speak to someone named "Number-only contact" or demand a customer name. A number is not verified identity: the call asks general owner-provided questions and records responses, without disclosing private account records or taking account/payment actions. Caller statements are reported for owner review, not verified payment or quotation acceptance.

Deploy/restart updated Trade and bridge, then start a new Talk to Sophie session so it advertises the updated arguments. Existing AI_OWNER_VOICE_SCHEDULED_CALLS_ENABLED, callback/logging permissions, DID mappings and worker/cron setup still apply. No new environment variables or Firestore indexes are required. The cumulative bridge archive includes the updated owner-requested greeting and metadata handling.

Offline tests cover unknown/unnamed numbers without customer records, explicit readback and confirmation, rejection of invalid/opted-out/reception numbers, direct-call dispatch, customer-requested rescheduling, old-worker isolation, and known-customer regressions. No live calls are placed by tests.
